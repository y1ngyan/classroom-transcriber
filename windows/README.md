# Windows 版切片

**当前做到：真实课堂录音格式 → 重采样 16k → 静音门控 → 10 秒滑窗（3 秒步长）→ whisper.cpp → 跨窗去重合并 → 中文文本。**
采集（WASAPI）、说话人分离、界面还没有。

## 它是什么

一个命令行程序：读任意常见格式的 WAV（16/24/32-bit 整数或 float32，44.1k/48k/…，单/双声道），
自己下混并重采样成 whisper 要的 16 kHz 单声道，按 10 秒窗 / 3 秒步长滑窗跑，跳掉静音窗，
把重叠窗的重复句子合并掉，按时间戳打印。

```
[00:00.00 -> 00:04.32] 今天讲梯度下降，它其实是在参数空间里找下降最快的方向。
[00:04.32 -> 00:09.10] 学习率太大会震荡，太小会收敛得很慢。
段数: 2
音频 1830.4 秒 · 取窗 611 · 解码 588 · 跳静音 23（214.0 秒）· 门控 开
```

（示例数字，不是某一次真实运行的记录；第二行是 stderr，stdout 只有转写结果。）

## 为什么先做这个

macOS 版的四层里三层是 Apple 独占（SwiftUI / AVFoundation / CoreML），只有 whisper.cpp 能直接跨平台。
所以先用这个切片把**「音频 → 推理 → 合并」这条链**钉死；界面没有意义，直到这条链在真实录音上能出正确的中文。

## 构建

需要 CMake ≥ 3.20 和 VS 2022（或 clang-cl）：

```powershell
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

首次配置会 `FetchContent` 拉 whisper.cpp（固定 tag v1.7.4），要求联网。
只要编核心库和测试、不要模型和网络：`-DCT_WITH_WHISPER=OFF`。

macOS 上做编译校验（不跑 Windows 也能验「代码编得过」）：

```bash
c++ -std=c++17 -I/opt/homebrew/include -L/opt/homebrew/lib \
    -lwhisper -lggml -lggml-base src/*.cpp -o /tmp/ct-win-check
```

## 跑

```powershell
build\Release\ct-win.exe ggml-medium-q5_0.bin lesson.wav zh
build\Release\ct-win.exe ggml-medium-q5_0.bin lesson.m4a.wav zh --gate off --verbose
```

| 参数 | 说明 |
|---|---|
| `<model.bin>` | whisper.cpp 的 ggml 模型（不在仓库里；`ggml-medium-q5_0.bin` 约 514 MB 是 macOS 版在用的那个） |
| `<audio.wav>` | 输入音频 |
| `[language]` | 默认 `zh` |
| `--gate on\|off` | 静音门控，**默认 on** |
| `--verbose` | 逐窗打印门控读数与合并变更（走 stderr） |
| `--scan <wav>` | 只逐窗扫门控并打印边界与余量，**不加载模型**（`ct-win.exe --scan lesson.wav`） |

模型去 whisper.cpp 的 Models 页拿。**也可以直接喂 44.1k/48k、float32、双声道的原始录音**，
不用先 ffmpeg 转（参见下面「重采样」一节）。

退出码：`2` 参数错 / `3` 音频错 / `4` 模型加载失败 / `5` 转写失败。无参数退 2，CI 的冒烟测试依赖这个约定。

## 重采样：为什么是线性插值、不用 libsamplerate

输入端支持 8/16/24/32-bit 整数 PCM 与 float32、44.1k/48k/任意常见采样率、1..8 声道。

**不引 libsamplerate 的理由**（这是被问过两次的问题，把账算清楚）：

1. **要解决的问题很小**：把一维 float 数组从 48k 落到 16k。libsamplerate 提供的是
   「任意比率 + 高质量多相 FIR + 状态机重采样器」，我们用不到其中的九成。
2. **它的高质量档用不上**：`SRC_SINC_BEST_QUALITY` 的收益在**宽带音乐**上能听出来；
   课堂录音的主要能量在 200–4000 Hz，8 kHz 以上本来就只有底噪和桌面碰撞。
3. **whisper 的前端不敏感**：输入进的是 log-mel（16 kHz 下每帧 25 ms、10 ms 跳），
   线性插值带来的高频滚降与那点混叠在 mel 域里会被平均掉一大截。
   ⚠️ 这一条是**信号层面的推理，没有实测**：真实课堂录音上「重采样前后转写文本是否一致」
   还需要一台有模型的机器才能量（见「验证到什么程度」）。
4. **多一个依赖 = 多一条 Windows 构建路径**：这个目录的存在意义是「最短能有多短」，
   现在整条链只依赖 whisper.cpp 一个外部库。
5. **线性插值可被逐样本钉住**：常数输入 → 同一常数，斜坡输入 → 斜坡，长度是
   `round(n * 16000 / rate)`。这些都能写成断言（`tests/test_main.cpp` 里就有），
   而第三方库的黑盒只能验「大概对」。

**已知代价**（写在这里，不装作没有）：线性插值在降采样时**没有抗混叠滤波**，
8 kHz 以上的成分会折叠回来。如果将来在真实录音上观察到「高频嘶声导致幻听式短句」，
正确做法是先在重采样前加一个 8 kHz 低通的 FIR（哪怕 15 抽头），而不是换成 libsamplerate。
**这个现象目前没有实测到**，所以没有提前加。

**下混规则**：只对非全零声道取平均。双声道同源时等价于普通平均；
USB 话筒常出现「只有一路有声、另一路整段数字静音」，那一路要被跳过——
取平均会把幅度砍半（-6 dB），而门控的 p90 判据贴着 0.01，砍半足以把真人说话推进「静音」。

## 滑窗：10 秒窗 / 3 秒步长

移植自 macOS 版 `WhisperWindowPipeline` 的取窗节奏：

- 检查点在 3 秒、6 秒、9 秒……每个检查点取「往回 10 秒」的后缀；
- 所以前三个窗是 3/6/9 秒的碎片（实时链路里缓冲只有那么多），之后每窗 10 秒、每次滑 3 秒；
- 收尾若还剩 ≥ 1 秒（`kMinimumFlushSeconds`，与 macOS 同值），补一窗；不足 1 秒不送模型
  （喂几百毫秒 whisper 会编出文本）。

**步长为什么不放大到 9.6 秒**（曾经这么试过）：9.6 秒只剩 0.4 秒重叠，macOS 上实测
**整窗丢话**——每一窗的开头段落在上一窗的覆盖之外，合并器又只能看到重叠区，两者叠加
就是整句消失。生产步长因此固定 3 秒（重叠 7 秒，一句话平均被解码三次）。
这个数是实测调出来的，所以这里**写死、不做命令行参数**。

## 静音门控（`--gate`）

判据与 macOS `SpeechGate` 逐字相同，20 ms 帧：

- 底噪 = 帧 RMS 的 p5，语音 = p90，语音帧阈值 = `max(底噪*3, 0.005)`；
- 语音帧占比 < **0.10** 且 整窗 p90 < **0.01** → 判静音，**整窗不进模型**；
- 两条都成立才跳（两个条件缺一不可）。第二条挡的是「电平均匀的连续人声」：
  整窗都在说话时 p5 取到的是人声本身 → 阈值被抬到人声之上 → 占比算成 0，
  只看第一条会把满窗人声判死。

**默认开**：静音幻觉是 macOS 上四次独立复现过的现象（120 秒麦克风静音会稳定长出
像真话的句子），门控是**事前**拦截，幻觉过滤器只能事后删。

`--gate off` 时一窗都不跳，取窗、解码、合并三条路径与没有门控时逐项一致（门控代码根本不执行），
所以 `off` 就是 A/B 对照的「改造前」那一臂。

**已知误判**（同样与 macOS 一致，不掩饰）：人离麦很远、p90 低于 0.01 的小声课堂会被判成静音。
这个边界要有真人小声说话的录音才能标定。这也是 `--gate off` 存在的理由。

## 跨窗合并

重叠窗会把同一句识别三次，合并器（移植自 macOS `WhisperWindowMerger`）按三趟匹配收敛：

1. 归一化文本 `.same` 且短者 ≥ 6 字 → 同一句，但要求候选与已有段的时间间隔 ≤ **一个步长**
   （没有这个上界，老师隔十几秒重复的口头禅会被并成一段，时间线也被搬走）；
2. `.similar`（编辑距离 ≤ 较长者的 20%）且区间距离 ≤ 1 秒 → 同一句的轻微重识别；
3. 时间真重叠且该段未定稿 → 视为内容修正，但若候选文本明确属于另一个已有段，则不按时间收编
   （否则整句原文会被覆盖，属于内容丢失）。

**取舍**：合并后时间戳取**最后一次识别**的位置，同一句最多向前漂一个步长。这是 macOS 版的既有取舍，
不在这里另立一套。

## 单元测试

`windows/tests/` 下是一个**不依赖 whisper、不依赖模型、不依赖网络**的可执行文件（CTest 里叫 `ct-win-tests`），
覆盖四块：

| 组 | 钉住什么 |
|---|---|
| 重采样 | 44.1k/48k 长度、四舍五入、**直流分量**、斜坡方向、1 kHz 过零数、16k 直通 |
| 下混 | 同源双声道、单边数字静音（不许砍半）、两路平均 |
| WAV 解析 | 16/24/32-bit 整数与 float32 都能读出正确数值（24-bit 符号扩展是坑） |
| 门控 | 常量 0.10/0.01 写死、两条判据的开区间边界、构造波形上的方向、已知误判 |
| 取窗 | 30/10.5/9.5/2/0.5 秒的窗数与起点毫秒、收尾窗、不越界 |
| 合并 | 重叠去重、相邻不同句不合并、口头禅重复要留两段、pendingTail、时间戳换算、排序 |

```powershell
ctest --test-dir build -C Release --output-on-failure
```

macOS 上（没有 cmake 也能跑）：

```bash
c++ -std=c++17 -Wall -Wextra -Wpedantic -Isrc src/audio.cpp src/speech_gate.cpp \
    src/window_plan.cpp src/merge.cpp tests/test_main.cpp -o /tmp/ct-win-tests && /tmp/ct-win-tests
```

测试**能真的红**：把 `kMinSpeechRatio` 改成 0.20、把步长改成 9.6、把插值权重写反、
把 `.similar` 的 20% 放宽到 30%、去掉第一趟去重、去掉收尾窗——每一条都有断言当场变红
（交付时逐个变异体验过）。

## 验证到什么程度

- macOS 上：`c++ -std=c++17 -Wall -Wextra -Wpedantic -I/opt/homebrew/include ...` 编过、**零告警**；
  单元测试 **239 条断言全绿**，12 个变异体（改阈值、改步长、写反插值权重、放宽 similar 阈值、
  去掉去重趟、去掉收尾窗、去掉 p90 判据……）**全部变红**。
- 合成夹具上跑通 `--scan`（80 秒、48 kHz、float32、双声道且右声道全零）：27 窗，前 7 窗判静音、
  中间 15 窗判有声、收尾 5 窗判静音（共跳 12 窗 / 108 秒），判静音批上界 0.070/0.00213 与
  判有声批下界 0.234/0.03536 之间有明显余量；下混正确取到了唯一有信号的那一路。
- 退出码 2（无参 / 未知选项 / `--gate` 乱值）、3（音频太短）、4（模型缺失）都实测过。
- **没验的**：Windows 上的实际构建与运行（本机是 macOS），以及真实课堂录音上的转写质量。
  前者由 `.github/workflows/windows-slice.yml` 在 `windows-latest` 上跑（构建 + CTest + 无参冒烟）；
  后者需要一台 Windows 机器 + 模型 + 真实录音。

## 已知限制

- 单进程、无流式：整段读完再跑（离线切片，不是产品形态）。内存随录音线性增长：
  3 小时 48k 立体声 float 录音峰值约 3.5 GB（原始交错样本 + 16k 单声道），
  data 块本身是分块读的，不额外多一份拷贝；
- 只支持 WAV（不解析 m4a/mp3）；float64 的 WAV 会明确报错；
- 重采样是线性插值，没有抗混叠滤波（代价与理由见上）；
- 合并后的时间戳可能比首次识别向前漂最多一个步长（与 macOS 同）；
- 门控对「人离麦很远的小声课堂」会误判成静音（与 macOS 同，`--gate off` 可关）。
