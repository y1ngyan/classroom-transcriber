# 被证否的做法（负结论也是交付物）

这个文件记的是**已经量过、证过有害或无效**的改动。写下来的目的不是自我批评，是防止后来人
（包括半年后的我们自己）把同一个坑再踩一遍——这些坑的共同点是：**看起来一定会更好，测出来更差**。

判据统一为四条，必须同时成立才算「更好」：
段/字不掉 · 用户可见重复为 0 · 不可信段占比不上升 · CPU/延迟真降。

---

## 1. 窗口步长 9.6 秒（重叠 0.4 秒）

**想法**：步长越大，重叠越多余，CPU 越省。
**做法**：`--step 9.6`，同一段真人录音跑两遍。
**结果**：

| 步长 | 段数 | 字数 | 覆盖率 | 现象 |
|---|---|---|---|---|
| 3.0 秒 | 24 | 218 | 97.5% | 正常 |
| 9.6 秒 | 13 | 201 | 95.4% | 第 9 窗整窗空白；48–67s、73–86s 两段空缺 |

两遍逐项一致（2/2 复现）。并用 `--gate-scan` 独立核对 38 个窗：**无一窗被判静音**
（77/80/83 秒三处语音帧占比 0.568/0.614/0.614）——所以不是门控误杀，是步长边界漏认。

**结论**：默认 3.0 秒，9.6 秒不开放配置。省的那点 CPU 换的是整段丢话。

## 2. 静音边界切窗（窗内按帧切静音，只解语音）

**想法**：门控只跳整窗，静音与说话同窗时仍整窗解码。按帧边界切段、只把语音送解码，
应该既省 CPU 又不丢内容。
**做法**：`CLASSROOM_SPEECH_COMPACTION=on`，同二进制、同一段 120 秒录音、只翻开关。

| 指标 | 关 | 开 |
|---|---|---|
| 送进解码的音频 | 360.0 秒 | 292.4 秒（切掉 18.8%） |
| user CPU | **27.31 秒** | **30.53 秒（+11.8%，没省）** |
| 段数 / 字数 | 24 / 218 | 39 / 336 |
| 覆盖率 | 97.5% | 100% |
| 不可信段占比 | 46% | **64%** |
| 用户可见重复 | 0 | **2** |

更要紧的是正文：

```
35 [00:01:51] 因为我都知道这个人是偏见的,偏见的,听得到的
37 [00:01:57] 偏见的吗?
38 [00:01:58] 偏见的,听得到的
```

三段互为回声（repetition loop），另有把三个不相关片段拼成 10 秒一条的段落。
字号 +54% 不是找回内容，是切碎之后模型进了循环。

**结论**：默认关，不合并。下一次迭代必须先把块变大：窗内 <0.4 秒静音不切、
单块不短于 2 秒、块间留 0.2 秒余量、只在静音占比 >30% 的窗才切。

## 3. 重转时补 AGC / 增益

**想法**：小声的课堂录音，重转前先补增益，应该更好认。
**结果**：覆盖率 0.684 → **0.591**（补了反而更差）。
**结论**：重转默认不加增益。小声问题的正解是换麦或贴近声源，不是事后放大——
放大同时也放大房间噪声与混响，识别率反而掉。

---

## 这类改动为什么值得单独记

三次都是「理论上一定更好」的优化，三次都让**指标变坏**。它们的共同陷阱是：
优化目标（省 CPU、提音量）和真实目标（用户复习时能不能看懂这节课）不是同一个东西，
而指标一旦只看前者，退化永远发现不了。
